# Agent Baseline Evidence Lab v0.10.0

v0.10.0 adds a fail-closed **Controlled Experiment Protocol** so a before/after governance delta is not silently presented as causal evidence when the two runs are not materially comparable.

## Highlights

- **Controlled Experiment Protocol** — independently evaluates whether two verified evidence bundles are suitable for bounded causal interpretation.
- **Three explicit outcomes** — `ELIGIBLE`, `NOT_ELIGIBLE`, and `INSUFFICIENT_EVIDENCE`.
- **Measured invariants** — compares Agent Baseline version, agent identity, task ID, task SHA-256, initial workspace SHA-256, agent runtime and Docker Sandbox runtime fingerprint.
- **Treatment fingerprint** — derives a deterministic governance-treatment fingerprint from network controls, MCP registrations, capability profile, MCP policy declarations, declared access and declared capabilities.
- **Fail-closed missing evidence** — an unavailable required invariant yields `INSUFFICIENT_EVIDENCE`; absence is never converted into a match.
- **No-treatment protection** — matching invariants with an unchanged treatment yields `NOT_ELIGIBLE`, making repeatability evidence distinct from a treatment experiment.
- **Recomputable statement** — the JSON experiment statement can be independently rebuilt from the before/after evidence bundles and tampering is detected.
- **HTML customer report** — generates a readable invariant/treatment matrix alongside the machine-readable JSON statement.
- **Ed25519 signing workflow** — experiment statements can be signed and verified with the same local trust material used by the rest of the evidence lifecycle.
- **Customer-facing workflow** — Makefile targets make creation, verification and signing repeatable.

## Why it matters

The project now separates three questions that are often conflated in technical PoCs:

1. **What is the observed control posture?** — assessment evidence.
2. **What changed between two verified runs?** — Governance Delta.
3. **Were the two runs sufficiently controlled to discuss the governance change as a causal factor?** — Controlled Experiment Protocol.

A status improvement is therefore not automatically described as a treatment effect.

## Usage

Create the experiment statement:

```bash
make experiment-protocol \
  BEFORE=evidence/abl-<before> \
  AFTER=evidence/abl-<after>
```

Verify by recomputation:

```bash
make experiment-protocol-verify \
  BEFORE=evidence/abl-<before> \
  AFTER=evidence/abl-<after>
```

Sign and verify:

```bash
make experiment-protocol-sign \
  BEFORE=evidence/abl-<before> \
  AFTER=evidence/abl-<after>

make experiment-protocol-sign-verify
```

Outputs:

```text
reports/controlled-experiment.json
reports/controlled-experiment.html
reports/controlled-experiment.json.ed25519.json
```

## Eligibility semantics

### `ELIGIBLE`

All required measured invariants match and the declared governance treatment differs.

### `NOT_ELIGIBLE`

A measured required invariant differs, or no governance treatment change was observed.

### `INSUFFICIENT_EVIDENCE`

At least one required invariant cannot be established from the supplied evidence.

## Claims boundary

`ELIGIBLE` means the required **measured** invariants match and the declared governance treatment differs. It does not prove causality, exclude unmeasured confounders, guarantee telemetry completeness, or establish official Docker or Agent Baseline conformance.
