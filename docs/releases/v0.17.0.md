# v0.17.0 — Standalone workspace and protected signing keys

A release wheel can now run the complete dry-run and signed presentation without a repository checkout:

```bash
abl init my-evidence-lab
cd my-evidence-lab
abl-trust --dry-run --scout-mode off
abl-present --open
```

The wheel bundles the maintained configurations, tasks, sample application, tests, Dockerfile checker and policy examples. Initialization creates a new directory and generates local keys. Existing destinations are rejected. CI and the release workflow exercise the installed package outside the checkout, including a workspace path with spaces.

Key generation exclusively creates new files and rejects existing keys or symlinks. Private files use `0600` on POSIX; newly created key directories use `0700`. Failed writes remove only newly created key files. The live preflight and trust flow validate that the persisted public and private keys match before execution. Rotation is an explicit procedure using new key paths while retaining historical verification material.

Signature and key parsing now rejects unknown schema versions, duplicate JSON fields, malformed encodings, mismatched key IDs and oversized metadata. Missing or malformed verification inputs return failure. External verification requires the supplied and embedded public keys to match. Hashing and signature verification use the same subject snapshot.

Existing correctly formed v1 signatures remain compatible. Old key permissions are not changed automatically. Unknown or inconsistent signing metadata accepted by older releases is intentionally rejected. Local key possession does not establish signer identity, and the dry-run is not live enforcement evidence.
