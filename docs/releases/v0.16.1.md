# v0.16.1 — Bind presentation claims to signed evidence

This patch fixes two ways that incomplete or changed reports could be presented too positively.

## Correctness

- `abl-present` checks displayed HTML/JSON files against their exact signed handoff members. A valid ZIP no longer authenticates unrelated neighboring files implicitly.
- Presentation verifies run identity, recorded handoff digest, public-key continuity, dry-run state and summary statuses against packaged evidence. Changed reports, swapped handoffs, unknown summary schemas and paths escaping the project root are rejected.
- Presentation lineage status describes signed packaged evidence. It does not rerun workspace or OCI verification, and a local key does not prove signer identity.
- The decision brief records an evidence gap for empty or entirely `N/A` assessments. Malformed entries, unknown statuses and duplicate control IDs are rejected.
- Incomplete optional artifact verification remains an evidence gap even when no artifact gate is required.

## Usability and verification

The README starts with the customer question, expected outputs and a reproducible dry-run. The demo guide explains exact-run selection, verification boundaries and customer-facing discussion points.

Regression tests use real Ed25519 signatures for presentation and cover altered external files, summary changes, handoff substitution, signature mismatch and path traversal. CI exercises presentation after the full dry-run and adds Python 3.11/Linux and Python 3.12/macOS compatibility checks.

Existing v0.16.0 handoffs and schema versions remain supported. A damaged or inconsistent local presentation must be regenerated from the original run; editing its summary to force a positive status is intentionally rejected. No live Docker enforcement result or measured customer outcome is claimed by these tests.
