# v0.16.0 — Verified Remediation Transition Pack

v0.16.0 combines governance and OCI artifact transition evidence into one signed, portable customer handoff while deliberately preserving their separate semantics.

## New `abl-transition` CLI

Create a remediation transition handoff from two verified governance runs and two verified trusted-artifact reports:

```bash
abl-transition create \
  evidence/abl-before \
  evidence/abl-after \
  reports/before-trusted-artifact.json \
  reports/after-trusted-artifact.json \
  --output reports/remediation-transition.zip
```

Verify the portable handoff:

```bash
abl-transition verify \
  reports/remediation-transition.zip \
  --signature reports/remediation-transition.zip.ed25519.json \
  --public .abl/keys/attestation-public.json
```

When the original trusted-artifact reports and referenced OCI archives are locally available, request full source recomputation:

```bash
abl-transition verify \
  reports/remediation-transition.zip \
  --signature reports/remediation-transition.zip.ed25519.json \
  --public .abl/keys/attestation-public.json \
  --before-trusted-artifact reports/before-trusted-artifact.json \
  --after-trusted-artifact reports/after-trusted-artifact.json \
  --root .
```

## Two evidence planes, one handoff

The transition pack contains two deliberately independent evidence planes:

- the existing signed Governance Comparison Pack and recomputable Governance Delta;
- the signed OCI Artifact Diff plus the exact before/after trusted-artifact reports used to produce it.

A governance transition is not treated as proof of an artifact transition. An artifact transition is not treated as proof of a governance improvement. Their co-occurrence is not treated as causal evidence.

## Portable verification

Without copying OCI layer archives into the handoff, a recipient can still verify:

- deterministic ZIP member inventory, SHA-256 and size binding;
- duplicate and unsafe member-path rejection;
- private-key exclusion;
- the nested governance comparison pack and its signature;
- public-key continuity between the nested governance pack and transition pack;
- the OCI Artifact Diff signature;
- SHA-256 binding from the signed artifact diff to the exact embedded trusted-artifact reports;
- before/after run IDs and artifact classification in the transition manifest;
- optional external verification of the outer transition-pack signature.

## Full OCI recomputation

When both original trusted-artifact reports are supplied, they must be byte-identical to the reports embedded in the transition pack.

The artifact diff verifier then replays the original source evidence and checks:

- each trusted-artifact report to OCI archive SHA-256 binding;
- recursive OCI graph integrity;
- Docker attestation-manifest structure;
- SPDX SBOM presence;
- SLSA provenance presence;
- attestation subject binding;
- reconstruction of the complete OCI Artifact Diff classification and changes.

Both before and after reports are required for this mode. A partial full-recompute request fails closed.

## Portable by design

OCI archives are intentionally not duplicated into the remediation handoff. This avoids turning a compact customer evidence package into another image-distribution mechanism while preserving a verifiable path back to the original artifacts.

Portable verification proves signed report/diff binding. Full source recomputation requires access to the original OCI archives referenced by the trusted-artifact reports.

## Deterministic and signed

The transition ZIP uses deterministic member timestamps and permissions, an explicit member manifest, SHA-256 binding and Ed25519 signatures. The same public verification key is required across the nested governance comparison, artifact diff and outer transition handoff.

The key demonstrates signer continuity only. It does not by itself establish organizational identity.

## Release hardening

The clean-wheel release smoke now requires `abl-transition --help` to succeed after installation of the built wheel, alongside the existing trust, policy, acceptance and artifact-diff entrypoints.

## Claims boundary

A verified transition pack proves that the included governance and artifact transition evidence is cryptographically bound to the signed handoff and, in full-recompute mode, that the OCI Artifact Diff can be reconstructed from the supplied source reports and archives.

It does not prove causality, remediation completeness, telemetry completeness, vulnerability absence, behavioral equivalence, external signer identity, compliance, Docker certification or deployment authorization.
