# v0.15.0 — Deterministic verified OCI artifact diff

v0.15.0 adds a verified before/after comparison layer for trusted OCI artifacts.

The goal is deliberately stronger than comparing archive hashes: the release distinguishes **OCI tar byte identity** from identity of the independently verified runnable image graph and selected supply-chain evidence.

## New `abl-artifact-diff` CLI

Create a comparison from two `VERIFIED` trusted-artifact reports:

```bash
abl-artifact-diff create \
  reports/before/trusted-artifact.json \
  reports/after/trusted-artifact.json \
  --output reports/oci-artifact-diff.json \
  --html reports/oci-artifact-diff.html
```

Recompute it independently:

```bash
abl-artifact-diff verify \
  reports/oci-artifact-diff.json \
  reports/before/trusted-artifact.json \
  reports/after/trusted-artifact.json
```

Both source OCI archives are re-verified before comparison. A stale report, mutated archive, invalid OCI graph or invalid attestation subject binding fails closed.

## Three separate identities

Each artifact snapshot now records:

1. **archive SHA-256** — exact OCI tar bytes;
2. **runnable graph fingerprint** — canonical platform/manifest/config/ordered-layer identity;
3. **supply-chain evidence fingerprint** — canonical predicate types, normalized SLSA provenance materials, SBOM/provenance presence and subject-binding validity.

This prevents tar member ordering or archive header metadata from being mislabeled as an application artifact change.

## Explicit classifications

The comparison produces one of:

- `IDENTICAL` — archive bytes and modeled identities are unchanged;
- `REPACKAGED_EQUIVALENT` — archive bytes differ while modeled runnable graph and selected supply-chain evidence remain stable;
- `BUILD_EVIDENCE_CHANGED` — runnable graph remains stable while provenance/base-image/Scout evidence changes;
- `ARTIFACT_CHANGED` — runnable manifest/config/layer graph changes.

`REPACKAGED_EQUIVALENT` is bounded to the fields modeled by this verifier. It is not a universal behavioral-equivalence claim.

## Provenance material transitions

The diff normalizes SLSA provenance materials from both legacy `materials` and provenance-v1 `buildDefinition.resolvedDependencies` shapes.

For a material URI present on both sides, a digest transition is emitted explicitly rather than being buried in an opaque attestation digest change.

The tool intentionally does **not** infer that every provenance material is a base image. Dockerfile base-image evidence remains a separate source.

## Raw attestation changes remain visible

Attestation statement digests are still diffed independently. This means a build invocation nonce or timestamp can be visible as changed while leaving the runnable graph and selected provenance-material fingerprint unchanged.

## Verification and tamper detection

The verifier reconstructs both snapshots and the complete diff from source evidence. Mutation of:

- the generated diff;
- either trusted-artifact report;
- either OCI archive;

invalidates verification.

## Customer value

The new layer supports higher-quality remediation and hardening discussions, including:

- distinguishing a repack from a real runnable image change;
- identifying added/removed layers;
- exposing config/manifest transitions;
- showing provenance material digest movement;
- separating declared base-image-reference changes from provenance materials;
- showing Scout status movement independently of runnable graph identity.

## Claims boundary

The artifact diff describes observed cryptographic and metadata transitions. It does not prove why a change happened, establish causality, guarantee behavioral equivalence, prove vulnerability absence, establish external signer identity or authorize deployment.
