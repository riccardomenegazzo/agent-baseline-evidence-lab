# Agent Baseline Evidence Lab v0.10.1

v0.10.1 is a presentation, documentation and supply-chain hardening release. It does **not** change the Agent Baseline control semantics introduced in v0.10.0; it makes the project easier to review, safer to maintain and more coherent as a reusable customer-facing PoC.

## Highlights

- **Rebuilt project front door** — the README now explains the enterprise problem, evidence lifecycle, live/dry-run paths, Governance Delta and Controlled Experiment Protocol before diving into implementation detail.
- **Executive Overview** — a concise non-technical entry point for recruiting, leadership and cross-functional stakeholders.
- **Customer Demo Guide** — a neutral 7–10 minute walkthrough focused on evidence, independent verification and claims boundaries.
- **Stronger Customer PoC** — adds hypothesis, scope, measurable success criteria, before/after experiment design, deliverables and decision questions.
- **Roadmap aligned through v0.10** — clearly separates implemented capability from environment-dependent live evidence and future trust integrations.
- **Pinned CI dependencies** — core GitHub Actions are pinned by commit SHA rather than floating major-version tags.
- **Dependency maintenance** — Dependabot configuration covers Python dependencies and GitHub Actions.
- **Complete Apache-2.0 license** — replaces the prior short application notice with the complete standard license text.
- **Expanded Security Policy** — documents safe-probe rules, sensitive evidence handling, disclosure guidance and high-priority verifier/packaging vulnerability classes.
- **Expanded contribution contract** — defines evidence semantics, negative-test expectations and safety requirements for new evaluators.
- **Version-agnostic download guide** — future releases no longer make the installation documentation immediately stale.
- **Package metadata** — adds project URLs, explicit license file inclusion and Python-version classifiers.

## CI and release hardening

The main CI now pins:

- `actions/checkout` by commit SHA;
- `actions/setup-python` by commit SHA;
- `actions/upload-artifact` by commit SHA.

It also smoke-tests the installed Controlled Experiment Protocol module alongside the existing package entrypoints.

The release workflow continues to publish only after a successful main CI and still refuses to overwrite an already-published version.

## Claims boundary

This remains a community implementation and assurance lab. Documentation polish, signatures, release checksums and successful CI do not turn the project into an official Docker or Agent Baseline conformance program. The project continues to distinguish product presence, observed enforcement, evidence integrity, external identity and causal interpretation.
