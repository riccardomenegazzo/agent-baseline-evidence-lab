# v0.11.2 — Portable evidence pack overlap fix

v0.11.2 is a targeted reliability patch for the live Customer Trust Flow.

## Fixed

- Customer evidence pack creation now safely reuses an existing ZIP member when the same physical artifact is referenced by more than one semantic role.
- The concrete live-demo failure involving `evidence/<run-id>/manifest.sha256.json` is resolved: the assessment manifest can be both primary assessment evidence and an incident artifact without being written twice.
- Conflicting duplicate content still fails closed. The packager only deduplicates when the bytes are identical.
- A regression test verifies that the overlapping incident reference produces exactly one ZIP member while preserving the incident linkage metadata.

## Version consistency

The package-level `agent_baseline_lab.__version__` value is aligned with the project metadata, and a regression test prevents future version drift.

## Safety and claim boundaries

This patch does not weaken evidence verification, signature verification, portable-path enforcement, or archive-integrity checks. It removes a false-positive packaging failure while retaining fail-closed behavior for genuinely conflicting archive entries.

## Distribution

Release artifacts are published only after CI succeeds. The release workflow builds wheel and sdist, records SHA-256 checksums and a release manifest, generates GitHub Artifact Attestations/SLSA provenance, verifies those attestations, and then publishes the GitHub Release.
