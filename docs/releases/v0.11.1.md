# v0.11.1 — Interview-safe live demo hardening

v0.11.1 is a focused usability and reliability patch on top of the v0.11 Customer Trust Flow.

It does not change the evidence model or weaken any verifier. The release hardens the path used for a live technical demo so that host prerequisites fail before agent execution, and so the resulting evidence can be presented without manually hunting through the report tree.

## Highlights

### Fail-closed live preflight

The new `abl-preflight` command checks the local environment before a live Docker-backed demonstration:

- host platform and architecture;
- Python 3.11+;
- Docker CLI and daemon reachability;
- Docker Buildx;
- Docker Scout availability according to `off`, `observe` or `gate` semantics;
- Docker Sandboxes CLI and control-plane reachability;
- inspectable sandbox policy state;
- presence of a host-managed OpenAI credential without reading or persisting the secret;
- verified Agent Baseline lock;
- local Ed25519 signing material;
- required demo assets.

An optional `--sandbox-smoke` mode creates a disposable shell sandbox, records a deny rule, executes a trivial command, confirms the policy is observable and removes the sandbox.

The result is also written as machine-readable JSON under `reports/demo-preflight.json`.

### Preflight integrated into `abl-trust`

Live `abl-trust` executions now run the preflight automatically before starting the Customer Trust Flow.

Useful modes:

```bash
abl-trust --preflight-only --preflight-smoke --scout-mode observe
abl-trust --scout-mode observe
```

A failed required preflight check prevents the live trust lifecycle from starting.

Dry-run remains CI-safe and deliberately skips host probing.

### Presentation helper

The new `abl-present` command independently verifies the final handoff and its Ed25519 signature against the external public key, then selects only the artifacts useful in a live review.

By default it prefers the newest **live** Customer Trust Flow over any newer dry-run, so an interview does not accidentally open rehearsal evidence. Exact selection is also supported:

```bash
abl-present
abl-present --open
abl-present --json
abl-present --run-id abl-<run-id>
```

The default presentation order is:

1. Customer Trust Flow HTML;
2. Customer Decision Brief;
3. Trusted Artifact and optional agent-to-artifact lineage;
4. signed Customer Trust Handoff.

The helper is intentionally not a replacement for the underlying assessment, OCI, lineage or claims-boundary verifiers.

### Five-minute customer demo guide

`docs/DEMO_GUIDE.md` now describes a compressed technical review:

```text
problem
  ↓
preflight
  ↓
governed agent execution
  ↓
trusted artifact + lineage
  ↓
decision + signed handoff
  ↓
controlled mutation test
```

The closing negative test demonstrates that trust is invalidated when either the post-agent workspace or the trusted OCI archive no longer matches the evidence chain.

## Safety and claim boundaries

This patch preserves the existing fail-closed semantics:

- a green preflight proves prerequisites, not successful future execution;
- Docker Scout `observe` mode does not silently become a gate;
- dry-run does not produce live containment or lineage claims;
- presence of a host-managed credential is checked without collecting the token;
- `abl-present` verifies the handoff before presenting it;
- automatic presentation selection prefers live evidence and labels dry-run state explicitly;
- no synthetic security score is introduced.

## Distribution

Release artifacts are produced only after CI succeeds. The release workflow builds wheel and sdist, records SHA-256 checksums and a release manifest, generates GitHub Artifact Attestations/SLSA provenance, verifies those attestations, and only then publishes the immutable GitHub Release.
